# 面试讲解材料

## 30 秒项目介绍

我做了一个面向通用图像的可追溯视觉助手。系统先用 Qwen3-VL 回答问题，
同时生成结构化的视觉证据目标，再通过 Grounding DINO 定位目标框、SAM 2.1
生成实例掩码。除了在线 Demo，我还设计了冻结的 Dev/Test 协议，把误差拆成
回答、目标抽取、检测和分割四个阶段，并实现断点续评、Hash 锁定和指标回放。
最终在 COCO held-out Test240 上达到 95% 存在性准确率、84.06% 目标 F1 和
59.17% 端到端完整证据成功率，单张 3090 平均延迟约 1.30 秒。我还在隔离的
Dev110 上测试了三类证据纠错方案；它们都没有超过 96.36% 的 Qwen 基线，
因此最终关闭答案改写，只保留证据定位和审计能力。

## 两分钟讲解

### 1. 背景与问题

视觉大模型可以生成自然语言答案，但答案通常缺少像素级依据。仅看答案正确率，
无法判断模型到底看到了什么，也无法区分“语义回答错了”和“目标定位失败了”。

### 2. 方案

我把系统拆成三个阶段：

1. Qwen3-VL 根据图像和问题输出 `answer` 与 `evidence_targets`。
2. Grounding DINO 根据目标短语做开放词汇检测。
3. SAM 2.1 以检测框为 prompt 生成实例掩码。

这样既保留 VLM 的语义理解能力，也能输出可视化的框、掩码和逐实例置信度。

### 3. 我的主要工作

- 完成本地离线模型部署和单卡推理集成。
- 设计任务感知结构化 Prompt、解析器和 COCO 类别规范化。
- 构建 listing、existence、relation 三类问题的 Dev60/Test240。
- 实现答案、目标、Box、Mask、端到端联合指标及失败归因。
- 实现断点续评、模型与数据 Hash 锁定、指标独立回放和 Gradio 展示。
- 构建 Verifier Dev110，离线比较 21 个 V1/V2 策略并实现 V3 对比类别复核，
  用预注册门槛决定模块是否可以进入 held-out 评测和最终部署。

### 4. 实验结果

最终 Test240 中，存在性准确率为 95%，空间关系 Balanced Accuracy 为
71.99%，目标抽取 Micro F1 为 84.06%，Box 和 Mask 的 IoU50 Micro F1
均为 50.21%。严格要求答案正确且全部证据完整时，端到端成功率为 59.17%。

Verifier Dev110 的 Qwen 基线准确率为 96.36%、F1 为 96.30%。V1 最佳配置
只有 1 个有效纠错却引入 4 个错误；V2 低阈值为 1 个有效、2 个错误；V3 为
0 个有效、1 个错误。因此没有 verifier 通过“准确率严格提升、F1 不下降、
净纠错为正”的联合门槛。

### 5. 结论

系统已经完成从语义回答到像素级证据的工程闭环，也通过分阶段指标暴露了主要
瓶颈：物体枚举召回、小目标定位以及密集实例分割。项目还证明了“有视觉证据”
不等于“可以安全改写答案”：简单置信度和语义复核会把相关类别误当成目标。
后续应接入公开 grounding/hallucination benchmark，并研究经过校准的拒答或
可学习 verifier，而不是继续在当前少量失败样本上调参。

## STAR 版本

**Situation**：视觉大模型回答可读，但缺少可验证的视觉依据，单一答案准确率也
无法定位错误阶段。

**Task**：在离线服务器和单卡 24 GB 显存约束下，搭建可运行、可评测、可展示的
通用 grounded VLM 系统。

**Action**：集成 Qwen3-VL、Grounding DINO、SAM 2.1；设计结构化输出接口和
任务感知 Prompt；构建冻结评测集；实现多阶段指标、失败分析、Hash 锁定和
Gradio 页面；另外构建独立 Dev110，对三类 evidence verifier 执行预注册消融。

**Result**：完成 240 个 held-out 问题零运行错误评测，达到 95% 存在性准确率、
84.06% 目标 F1、59.17% 完整证据成功率，并将平均推理延迟控制在 1.30 秒；
同时识别并拒绝了整体负增益的答案纠错模块，冻结 96.36% 的 Qwen 基线。

## 高频追问与参考回答

### 为什么不直接让 Qwen3-VL 输出框？

Qwen3-VL 擅长语义理解，但通用生成坐标的稳定性和像素级掩码能力有限。使用
Grounding DINO 和 SAM 2.1 可以获得可替换、可独立评测的检测与分割模块，
并将语义错误和定位错误分开分析。代价是多模型串联带来的延迟和误差传播。

### Grounding DINO 和 SAM 2.1 分别做什么？

Grounding DINO 解决“文本短语对应图像中的哪个区域”，输出开放词汇目标框；
SAM 2.1 接收这些框作为 prompt，将粗粒度区域细化为像素级实例掩码。DINO
决定找哪里，SAM 决定区域边界。

### 为什么需要 `evidence_targets`？

自由文本答案不能直接稳定地作为检测 prompt。结构化目标把答案中的关键实体
显式化，既是 VLM 与检测器之间的接口，也是可单独计算 precision、recall 和
F1 的中间监督信号。

### 为什么 Overall Accuracy 65.83%，端到端完整成功率只有 59.17%？

总体答案指标只要求回答正确；完整成功还要求所有必要证据都被正确提取，并在
IoU50 下完成定位。它是多个阶段的联合事件，因此一定更严格。两者的差距反映
了“答对但证据不完整”的样本。

### Box F1 和 Mask F1 为什么恰好相同？

这里报告的是 IoU50 下汇总 TP、FP、FN 后得到的 Micro F1。两个阶段在该阈值下
恰好产生了相同的总体计数，不代表每个实例的 Box IoU 与 Mask IoU 相同；
逐样本匹配结果和 Mean IoU 仍可能不同。

### 为什么空间关系使用 Balanced Accuracy？

测试集中的四种关系标签支持度不完全相同，普通 Accuracy 可能被多数类影响。
Balanced Accuracy 对各类别召回率取平均，更能反映 `above/below/left/right`
是否都学得合理。项目同时报告原始 Accuracy 和混淆矩阵。

### 如何保证没有在测试集上调参？

提示策略和阈值只在 Dev60 上选择，之后保存策略文件及 Hash。Test240 运行时
验证数据划分、Prompt、代码和配置 Hash；最终报告再次检查 240 个唯一 ID、
缺失文件、运行错误，并独立重算指标。测试结果只用于报告，不回流调参。

### v2 Prompt 为什么被选择？

在预先冻结的 Dev60 上，v2 将 Schema 有效率从 96.67% 提升到 100%，listing
Macro F1 提升 11.71 个百分点，target Micro F1 提升 12.22 个百分点，同时
满足预注册门槛。它并非所有指标都更高，例如 Box/Mask F1 有轻微下降，因此
选择依据是事先定义的联合门槛，而不是挑单个最好看的数字。

### 主要失败在哪里？

第一类是 listing 的长尾类别漏召回和同义词规范化；第二类是 Grounding DINO
在小目标、密集同类实例上的漏检或重复框；第三类是单个 listing 输出达到
192-token 上限，造成 JSON 截断。最终报告保留了这条失败，没有根据测试结果
修改生成长度。

### 如何在单张 RTX 3090 上运行？

Qwen3-VL-8B 使用半精度并通过 `CUDA_VISIBLE_DEVICES` 固定到目标 GPU；
Grounding DINO 和 SAM 2.1 复用同一张卡。Gradio 使用懒加载和单并发队列，
避免两个请求同时占用模型显存。最终峰值约 19.31 GB，低于 24 GB 显存。

### 多卡如何扩展？

更大的 VLM 可以使用 Transformers `device_map`、Accelerate 或 tensor
parallelism 切分；服务层也可以把 VLM 与 Grounded-SAM-2 放到不同 GPU，
通过队列传递结构化 targets。当前 8B 模型单卡可运行，所以优先保证协议稳定
和结果可复现，没有为了展示而增加多卡复杂度。

### 这个项目证明降低了幻觉吗？

当前结果证明系统能够生成并量化视觉证据。我也在隔离 Dev110 上完成了“原始
Qwen 对比三类 grounded verifier”的受控实验，但结果是负的：所有纠错策略都
降低或持平准确率，没有通过预注册门槛。因此我会表述为“为回答提供可审计
证据，并验证了简单后验纠错不足以安全降低错误”，不会声称已经降低幻觉。
POPE 等公开协议上的公平方法比较仍属于下一阶段。

### 为什么最终没有把 verifier 上线？

上线条件在实验前就固定为：准确率严格高于基线、F1 不下降、有效纠错数大于
错误纠正数。V1 最佳配置净纠错为 -3，V2 为 -1，V3 仍为 -1；高阈值 V2 虽然
与基线同分，但增加约 10.86 秒的离线串行开销且没有纠正任何样本。按照门槛，
最终只能保留 Qwen 基线。这个决定避免了用少数成功截图掩盖整体回归。

### 负结果为什么还能写进简历？

重点不是“尝试失败”，而是我完成了可证伪的机制设计：隔离开发集、GT-free
推理任务、21 组模块消融、V3 对比类别复核、指标重算和源文件哈希，并根据统一
门槛拒绝弱方案。真实工程中，能识别不该部署的模块和能做出一个模块同样重要。
面试时需要同时给出失败原因、部署决定和下一版假设，不能把负结果包装成提升。

### 为什么当前结果仍然有说服力？

它的价值首先是完整工程链路和严格实验过程：真实本地模型、像素级输出、冻结
测试、逐阶段指标、失败样本与可运行 Demo 都可检查。它不能替代公开 benchmark，
但比只展示若干成功截图更可复现。后续通过 POPE 和 RefCOCOg/GroundingME
补充外部可比性。
